# 210. A later hash change in the space editor focuses nothing

**Status:** Open · **Date:** 2026-10-29

**Evidence:** after the first landing, a change of the address's hash alone is the shell's: `useMainFocus` (`apps/web/src/shared/routing/focus/useMainFocus.ts`) focuses the element whose id the hash names. In the space editor that element is the section's card (`SectionCard`, `PricesLinkCard`, `ReadOnlyCard` and `PhotosCard` carry the id), a `div` with no `tabindex`, so `focus()` does nothing; the headings that take the focus (`tabIndex={-1}`, D6.8) sit inside it. So the editor's own navigation (`SectionNav`, `MissingChecklist`, links `to={{ hash }}`) scrolls but leaves the focus where it was. The first landing is not affected: `useHashLanding` (`features/spaces`) focuses the heading inside the named card. Found by lane W2 while building D6.8; not run in a browser.

**Resolves when:** `useMainFocus` focuses the named element's own focusable heading when the element takes no focus (as `useHashLanding` does), or the named element itself takes the focus.
