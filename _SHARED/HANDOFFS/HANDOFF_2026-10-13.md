## 3. The method

**One Work Item, seven phases** (workflow §2): analysis with the owner (scope, open decisions with
options and a recommendation, settled decisions now doubtful, size) → a short prompt → the worker
plans and **saves the plan, then stops** → you summarise the plan for the owner **section by section**,
list its open questions with recommendations, then write the **reply** (`PROMPT\<ITEM>_PLAN_REPLY.md`)
that says "save the plan, cut the branch from the latest main, build" → the worker builds, PR, CI
green, `CLEAN`, report → **review** → fixes → merge.

**The prompt template:** header (worker, folder, branch command, databases/ports, model and effort,
size cap, PLAN/REPORT paths, "follow the skills"); §1 task; §2 read first (only what the item needs;
the capability document first); §3 settled decisions D1…; §4 findings / issues and the numbering
range; §5 risks; §6 boundaries with the other open items (**name their files**, including test files
that change because a shared type changes); §7 checks (only the lanes the change can touch), the PR
(title ≤ 50, labels, `Closes #n`), the documents.

**Reviews.** An independent review (a separate conversation) when a PR touches > ~25 files,
authorization/security, a transaction, the schema, a dependency or CI. **The reviewer is the owner's
choice — usually OpenCode** (free). Never the conversation that built the PR (#62 was first reviewed by
its own author by mistake; we reran it). Write `PROMPT\REVIEW<n>_PROMPT.md`: read-only, run from the
main folder but **read only commit objects** (that folder is A's branch), pin the PR's current head,
concrete findings only, "Checked and fine", report to `REPORT\REVIEW<n>_<TOOL>_REPORT.md`. For design
PRs you check **conformance** yourself with two read-only subagents (against prompt, plan, reply,
decisions), then write one fixes list. The owner's visual review of every screen is **deferred to after
batch 6** (an OpenCode screenshot task then); only screens worker A is about to build get a short look
now.

**Small review findings → an Issue, not a new round** (the owner's rule): open an Issue naming it a
leftover of PR #n, comment on the PR, and the next PR touching that layer fixes it in its own commit
and `Closes` it. Fixes rounds otherwise fold into their commits (fixup + autosquash,
`--force-with-lease`), one "Review fixes" comment.

**Design batches — the new way (since 2026-10-13):** Claude Code (Opus 5.5, high) writes an
**execution-grade plan only** (every change, every string in both languages, every frame to check, the
PR text, the reviewer's checklist, the hazards); **OpenCode builds it** from
`PROMPT\FIX_<X>_EXEC.md` and **another OpenCode session reviews** it. You still check conformance and
merge.

**Parallel work (workflow §9, the rule by files, the owner's 2026-10-12):** items run in any layer at
once when (1) one schema change in flight, (2) one dependency change, (3) no two open items edit the
same code file (shared docs / append-only lists are fine — fast path), (4) every API item has its own
databases and ports. A web, B API remain the default split. **A merge that touches none of a PR's files
needs no new CI run** ("merge apart"); Issue #71 tightens its wording ("deletes no file **the PR
uses**"). When two PRs finish together and merge cleanly with each other, the owner accepted merging
them in sequence and watching `main`'s CI (it runs on every push to `main`) instead of a second rebase.

**The machine:** **one full test run at a time** (workers A and B check each other before
`test:component` / `test:api`; parallel lanes once made A's runs fail under load — finding 55). Docker
Desktop stops often: start it, then `docker start masaha-postgres-1`; never `db:up` from a second
folder (finding 48). `jq` is not installed in Git Bash — every prompt says "use `gh … --jq`". Long

## 9. Hazards learned

- A worker may plan from the wrong worktree (both design planners swapped folders, harmlessly): check
  that the plan names the right build folder.
- Two over-long commit subjects passed a plan reply once: count every subject in plans and replies.
- A reviewer "permitted" a 52-character subject: the rule has no exception.
- Two workers running full lanes at once made tests fail (finding 55).
- `npx serve`'s clean URLs drop query strings: the prototype has `serve.json` (`cleanUrls: false`);
  python's `http.server` works too.
- The prototype's scripts share globals: no object rest destructuring, no generic top-level names.
- A worker printed a secret from `.env` once while trying to mask it: remind workers to print keys only.
- **One OpenCode session per execution prompt.** On 2026-10-13 two sessions ran `FIX_ACCOUNT_EXEC` in
  `masaha-design-b` at once; the second noticed, stood down without touching the repo, but replaced
  the first one's server on 5347 (now PID 23716, same folder). The active executor was told to use it
  and stop it at its clean-up; check the port is free when it reports.
