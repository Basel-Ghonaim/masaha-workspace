# شرح F-5a: ماذا بُني في المصادقة، وأين

> مرجع لك لفهم الكود ولشرحه في المناقشة. المسارات كلها تحت `apps/api/src` ما لم يُذكر غير ذلك.

## 1. الصورة الكبيرة

المصادقة مقسمة على **أربع وحدات** في `modules/`. كل وحدة تستورد ما **تحتها** فقط:

```
auth        (L3)  المنسِّق: تدفقات الدخول الثمانية، بلا جداول
  ↓
space-links (L2)  "ما روابط هذا المستخدم بالمساحات؟" (للرد فقط)
  ↓
users       (L1)  الحساب: الهوية، وكلمة المرور، والإيقاف، وGoogle
  ↓
sessions    (L0)  الرموز: إصدار، وتدوير، وإبطال (لا يعرف إلا رقم المستخدم)
```

وحول الوحدات **منصة مشتركة** (`shared/`) تخدم الجميع، ولا تعرف شيئًا عن المجال:
- **`auth/`:** رمز الدخول وحارس المسارات؛
- **`rate-limit/`:** عدّاد حدود الطلبات؛
- **`http/`:** السجلات ورقم الطلب؛
- **`errors/`:** غلاف الأخطاء.

**`app.ts` هو جذر التركيب:** يبني كل الخدمات، ويربطها ببعض، ويركّب المسارات.

## 2. الوحدات وملفاتها

### `sessions` (L0): الرموز

| الملف | مسؤوليته |
|---|---|
| `tokens.ts` | توليد رمز عشوائي (32 بايت)، وحساب بصمته (SHA-256). **لا يُخزَّن إلا البصمة** |
| `sessions.repository.ts` | قراءة وكتابة جدولي رموز التجديد ورموز الاستعادة |
| `sessions.service.ts` | الإصدار، والتدوير مع مهلة 30 ثانية، وإبطال العائلة، وإبطال الكل، ورموز الاستعادة. الصلاحيات: تجديد 7 أيام، واستعادة ساعة |
| `sessionCookies.ts` | الـ cookie‏ان: `masaha_refresh` (سري) و`masaha_session` (تلميح للواجهة) |

### `users` (L1): الحساب

| الملف | مسؤوليته |
|---|---|
| `password.ts` | تشفير كلمة المرور (bcrypt بقوة 12) والتحقق منها، **مع مقارنة وهمية حين لا يوجد حساب** |
| `users.repository.ts` | جدول المستخدمين. **البصمة لا تُقرأ إلا في دالتين محددتين** |
| `users.service.ts` | قواعد الدخول: من يحق له، والتسجيل، والتحقق، وGoogle، وتغيير كلمة المرور |
| `users.routes.ts` و`users.controller.ts` | المسار `POST /me/password` |
| `users.mapper.ts` | شكل المستخدم في الرد |

### `space-links` (L2): الحد الأدنى
دالة واحدة: روابط المستخدم **النشطة** بالمساحات، الأقدم أولًا.

### `auth` (L3): التدفقات

| الملف | مسؤوليته |
|---|---|
| `auth.routes.ts` | المسارات الثمانية: التسجيل، والدخول، وGoogle، والتجديد، والخروج، ونسيت كلمة المرور، وفحص الرابط، والتعيين |
| `auth.controller.ts` | ترجمة HTTP: ضبط الـ cookies ومسحها، وأكواد الرد |
| `auth.service.ts` | **المنسِّق:** يستدعي الوحدات الثلاث تحته، ويملك المعاملات |
| `auth.limits.ts` | أرقام حدود الطلبات |
| `google.ts` | التحقق من رمز Google |
| `email/` | منفذ البريد ومحوّلاته: `log` (للتطوير)، و`smtp` (Gmail)، و`capped` (الحدود)، ورسالة الاستعادة بلغتين |

### المنصة المشتركة

| الملف | مسؤوليته |
|---|---|
| `shared/auth/accessToken.ts` | توقيع رمز الدخول والتحقق منه (HS256، 15 دقيقة) |
| `shared/auth/requireAuth.ts` | الحارس: 401 بلا رمز صالح، و403 إن كان مطلوبًا تغيير كلمة المرور |
| `shared/rate-limit/` | العدّاد في PostgreSQL، والمحدِّد، وتطبيع عنوان IP (مع تجميع IPv6 بـ /64) |
| `shared/http/requestLogging.ts` | رقم لكل طلب، وحجب الأسرار من السجلات |
| `db/transaction.ts` | `runInTransaction`: الطريق الوحيد لفتح معاملة |
| `packages/shared/src/auth.ts` | مخططات التحقق المشتركة مع الواجهة |

## 3. كيف يمر كل طلب، خطوة بخطوة

### الدخول: `POST /auth/login`
1. **الحد العام** (300 طلب لكل مستخدم، أو 1200 للزائر، كل 15 دقيقة).
2. **التحقق من المدخلات** بمخطط Zod المشترك.
3. **فحص حد الفشل** (لكل IP، ولكل IP + بريد). إن تجاوزه: 429.
4. **التحقق من كلمة المرور.** حساب غير موجود ← مقارنة وهمية، ثم 401، فلا يكشف الزمن شيئًا. **والإيقاف لا يُكشف إلا بعد كلمة مرور صحيحة.**
5. **عند الفشل يُسجَّل فشل.** **عند النجاح لا يُسجَّل شيء.**
6. **إصدار جلسة:** رمز تجديد جديد بعائلة جديدة، ورمز دخول، وروابط المساحات.
7. **الرد:** المستخدم ورمز الدخول، ومعهما الـ cookie‏ان.

### التجديد: `POST /auth/refresh`
1. قراءة الـ cookie، والبحث عن الرمز **ببصمته**.
2. المستخدم موقوف ← إبطال كل جلساته، ثم 403.
3. **التدوير داخل معاملة:**
   - **رمز لم يُستخدم:** يُصدر خلف في العائلة نفسها.
   - **استُخدم قبل أقل من 30 ثانية** (تبويبان معًا): يُصدر "أخ" في العائلة نفسها.
   - **استُخدم قبل أكثر من 30 ثانية** (علامة سرقة): **تُحذف العائلة كلها**، ثم 401.
4. الرد بجلسة جديدة، و**مسح الـ cookies عند 401 أو 403.**

### طلب محمي برمز منتهٍ
الحارس يتحقق من الرمز. منتهٍ أو غير صالح ← 401، فتجدده الواجهة (في F-5b). وإن كان الرمز يحمل "مطلوب تغيير كلمة المرور" والمسار غير مستثنى ← 403 `PASSWORD_CHANGE_REQUIRED`.

### الاستعادة: نسيت ← البريد ← الفحص ← التعيين
1. **نسيت:** يُعدّ كل طلب (لكل IP، ولكل IP + بريد). الحساب غير موجود أو موقوف ← **نفس الرد 202 دون إرسال**. وإلا: رمز جديد يحل محل القديم، ورسالة بالرابط `/reset-password#token=…` (بعد `#`، فلا يصل إلى أي خادم أو سجل).
2. **الفحص:** قراءة فقط. صالح ← بريد الحساب، وإلا ← `RESET_TOKEN_INVALID` لكل الحالات.
3. **التعيين:** في معاملة واحدة: استهلاك الرمز بأمر ذري واحد، ثم ضبط كلمة المرور (فتسقط علامة "مطلوب التغيير")، ثم إبطال كل الجلسات. الرد 204، والمستخدم يدخل من جديد.

### Google: `POST /auth/google`
1. التحقق من رمز Google: المُصدر، والجمهور (معرّف مسحة)، والانتهاء، و**البريد موثّق عند Google**.
2. حساب مرتبط سابقًا ← دخول. بريد يطابق حسابًا ← **ربط تلقائي** (`linked: true`). جديد ← حساب `USER` بلا كلمة مرور.

### تغيير كلمة المرور: `POST /me/password`
- **إجباري** (موظف بكلمة مؤقتة) أو **حساب Google بلا كلمة:** لا تُطلب الكلمة الحالية.
- **طوعي:** الكلمة الحالية مطلوبة. خاطئة ← 400 `CURRENT_PASSWORD_INCORRECT`.
- بعدها، في معاملة واحدة: الكلمة الجديدة، ثم **إبطال كل الجلسات**، ثم **جلسة جديدة لهذا الجهاز**، فلا يخرج المستخدم.

## 4. أين تعيش كل قاعدة أمنية

| القاعدة | المكان |
|---|---|
| تخزين البصمة لا الرمز | `sessions/tokens.ts` |
| التدوير والمهلة وإبطال العائلة | `sessions/sessions.service.ts` (`rotate`) |
| إعدادات الـ cookies (HttpOnly، وStrict، والمسار) | `sessions/sessionCookies.ts` |
| رمز الدخول (HS256 مثبّت) | `shared/auth/accessToken.ts` |
| بوابة التغيير الإجباري | `shared/auth/requireAuth.ts` |
| المقارنة الوهمية ضد كشف الحسابات | `users/password.ts` |
| فحص الإيقاف | `users/users.service.ts` (`assertMaySignIn`) |
| التحقق من Google | `auth/google.ts` |
| استهلاك رمز الاستعادة مرة واحدة | `sessions/sessions.repository.ts` (`consumeResetToken`) |
| الرابط بعد `#` | `auth/email/resetEmail.ts` |
| رفض الإقلاع في الإنتاج دون SMTP | `config/env.ts` |
| حدود البريد (3/ساعة لكل مستلم، و100/يوم) | `auth/email/cappedEmailSender.ts` |
| عدّاد الحدود والفشل فقط | `shared/rate-limit/` و`auth.service.ts` (`limitFailures`) |
| رقم الطلب وحجب الأسرار | `shared/http/requestLogging.ts` |
| قاعدة المستويات | `eslint.config.js` |

## 5. قاعدة البيانات

| التغيير | المعنى |
|---|---|
| عمود `family_id` في `refresh_tokens` | العائلة: كل رموز جلسة جهاز واحد. والرموز القديمة أُعطيت رقمها |
| جدول `rate_limits` | العدّاد المشترك لحدود الطلبات وحدود البريد |

## 6. ما يجب أن تضبطه في `apps/api/.env`

| المتغير | |
|---|---|
| `JWT_SECRET` | **إلزامي،** 32 حرفًا على الأقل، **وإلا لا يعمل الخادم** |
| `GOOGLE_CLIENT_ID` | اختياري محليًا (بدونه يعيد Google 503)، وإلزامي في الإنتاج |
| `EMAIL_MODE` | `log` افتراضيًا (يطبع الرابط)، و`smtp` للإرسال الفعلي |
| `SMTP_HOST`، `SMTP_USER`، `SMTP_PASSWORD`، `EMAIL_FROM` | مع `smtp` فقط: Gmail وكلمة مرور التطبيق |
| `SMTP_PORT`، `SMTP_SECURE` | اختياريان (465 وtrue افتراضيًا) |
| `TRUST_PROXY` | اختياري محليًا. يحدد كيف يُقرأ عنوان IP خلف الـ proxy |
