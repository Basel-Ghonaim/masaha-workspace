## 4. The two constraints that shape the build

**(a) The bundle's CSS is prebuilt.** `_ds_bundle.css` was generated by scanning the *original*
prototype, so it holds only the classes the original already used. A new class is **silently dead**.
Verified present: `md:*`/`lg:*` layout variants, `sr-only`, `whitespace-nowrap`, `text-heading-1…3`.
Verified **absent**: `focus:not-sr-only`, `not-sr-only`, `focus:absolute`, `md:table-cell`,
`lg:table-cell`, `col-span-full`. Already dead in the prototype today: `min-h-14` and `md:inline` in
`owner.jsx`/`admin.jsx`, `hover:opacity-90`, `-mt-3`, `h-28`, `md:w-44`, `md:w-72`, `md:max-w-32`.

So: prefer **conditional rendering in JSX** over a new class; where a class is genuinely needed, add
a **layout-only rule** to `masaha/masaha.css`, which already exists for exactly this (`.num-iso`,
`.sidebar-stick`, `.scroll-mt-20`), using existing tokens only.

**(b) `docs/design/` is excluded from ESLint (`eslint.config.js:193`) and Prettier
(`.prettierignore`)**, and no test lane owns it. There is no automatic net: one bad edit blanks a
page. Substitutes are in §10.

**What the vendored bundle actually has** (it predates parts of the code's layer):
- **No `PageHeader`**, **no `SidebarText`.** P1's header is a prototype-level helper in `shared.jsx`;
  SH-006 uses `SidebarHeader`'s own `mark` prop, which already makes its children `sr-only` in
  tablet mode — exactly what SH-006 asks for.
- **`Pagination` has no page state** — a composition primitive, used on zero pages today.
  `PaginationSummary` is phone-only (`md:hidden`); the desktop summary goes in `DataTable`'s
  `summary` slot, the `Pagination` in its `pagination` slot.
- **`DataTable` switches to cards at 768, not 1024, and has no column-priority prop** — hence
  SH-007 below. Columns hide per breakpoint through `meta: { className }`.
- **`AlertDialogAction` takes `variant`** (P9 buildable). **`Button loading` is silently dropped
  under `asChild`** (matters for P8). **`Toaster` passes `offset`/`mobileOffset` through to sonner**,
  so P8's "toasts above the bottom bar" is buildable without SH-012.

### P8 · Every action says what happened *(amended twice)*

success toast, and **every money action gets one naming its amount**.

destructive `Alert` inside the open dialog or sheet, which keeps its input, or a `toast.error` with
«إعادة المحاولة» on a page; `?state=ratelimit` reuses `auth.jsx:6`'s one string, lifted to
`shared.jsx` so the dashboard can use it. `PageToaster` takes an `offset` so toasts clear the desk's
bottom bar. **Every new parameter is listed in `INDEX.md`.**

  «إلغاء» survives only as the verb of voiding a payment. The void dialog's reversed footer order is
  brought in line.
- **Not built:** the "sign out of all devices" dialog (`Settings.html:157`) — dropped from v1.
